# Сервис построения дорог

Сервис рассчитывает автомобильные и пешие участки, ищет адреса, места и исторические здания для прогулок. Редактор соединяет участки через промежуточные точки. Снимки для публикаций, их печать и медиа обслуживает document-service.

## Контракт

`POST /api/routing/v1/road`, `Content-Type: application/json`

```json
{"start":{"longitude":30.31,"latitude":59.93},"end":{"longitude":30.32,"latitude":59.94},"mode":"foot"}
```

Ответ содержит ломаную `coordinates` в порядке `[longitude, latitude]`, `distanceMeters` и `durationSeconds`. Режимы — `car` и `foot`. Предел по прямой составляет 1 500 км для автомобиля и 400 км для пешехода. Ошибка содержит поля `error` и `status`. Код HTTP 400 означает ошибку данных или превышение расстояния, 422 — отсутствие пути, 429 — занятый сервис либо ограничение провайдера, 503 — недоступность маршрутизации.

## Архитектура

Домен проверяет точки, режим и допустимое расстояние. Прикладной сценарий `CalculateRoad` получает упорядоченный список реализаций порта `RoadProvider`. Он пропускает одновременно один расчёт, перебирает доступные стратегии и возвращает первый успешный результат. При отказе всех провайдеров возвращается причина последнего отказа. HTTP-контроллер переводит JSON в доменный запрос. Пакет infrastructure содержит протоколы и ограничения конкретных провайдеров. Направление зависимостей проверяет ArchUnit.

Порядок по умолчанию — BRouter HTTP, Valhalla, затем локальный BRouter. При включении OSRM он стоит перед локальным BRouter. Переменные окружения и значения по умолчанию находятся в [application.yml](src/main/resources/application.yml).

## API прогулок

Префикс `/api/walks/v1` обслуживает `/addresses`, `/places` и тематический поиск, `/buildings`, `/maps/providers`. Когда пользователь запрашивает фотографии для печати, сервис регистрирует медиа через HTTP-порт `PrintMedia`. В базе маршрутизации хранятся геоданные и каталог мест. Движки маршрутизации используют отдельный файловый кэш графов.

В PostgreSQL сервис читает схему `routing`. Скрипт развёртывания переносит существующие таблицы `building_history` и `mystic_places` с индексами и последовательностями. Данные конструктора остаются в `public`. При развёртывании с H2 старые геоданные читаются из остановленной базы конструктора и копируются в файл сервиса маршрутизации.

## Локальный запуск

Из каталога ticket-pdf

```sh
mvn -f routing-service/pom.xml clean verify
java -jar routing-service/target/routing-service-1.0.0.jar
```

Порт по умолчанию — 8093. Для локального расчёта через JAR нужны BRouter и профили в `BROUTER_HOME`. Контейнер поставляет их в образе. Кэш графов хранится в `BROUTER_CACHE`. Проверка готовности — `GET /actuator/health`. Vite в ticket-editor проксирует префикс `/api/routing/` на этот порт, адрес можно изменить через `ROUTING_SERVICE_URL`.

В развёртывании ticket-infra собирает образ `codoc-routing`, запускает его в отдельном контейнере с томом для графов и направляет на него публичный запрос через Nginx. Для обновления нужны согласованные версии клиента, инфраструктуры и сервиса. Клиенты со старым адресом требуют обновления.
