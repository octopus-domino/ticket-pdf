# ADR 0003 · проверяемые границы в существующей топологии

Статус — предложено в Phase 1.

## Контекст

Четыре репозитория уже образуют несколько клиентов, два Java runtime и операционную конфигурацию. Между сервисами работают HTTP- и iframe-контракты. Существуют сохранённые снимки и публичные ссылки, которые должны продолжать открываться. [Аудит](../ARCHITECTURE-AS-IS.md) выявил нарушения внутренних зависимостей, пробелы в диагностике и конкретные риски готовности и доставки.

## Решение

Укреплять границы сценариев поверх существующей топологии. Выпуск и состояние схемы проверять в disposable окружении. Вводить диагностические правила первым шагом. Показать отдельно болевые точки совместимости и зависимости, которые допустимы публичным контрактом. Перейти на полноценный репозиторно-атрибутируемый backend-артефакт после появления rollback-проверки.

## Последствия

Пользовательские ссылки, данные, модули и стек сохраняются. Некоторое время новые и старые границы будут сосуществовать. Каждый отдельный PR получает собственный rollback. Решение не вводит дополнительные микросервисы и не запускает миграцию. Изменение этого решения требует измеренной причины и отдельного ADR.
