# ADR 0004. Снимок прогулки Private Journey → CoDoc

## Контекст

ARC-022. `ShareModal` публикует `private-walk:complete`. Его принимают `TripWalkImport` и `RoutePlacePanel`. Прежние приёмники разбирали имя, точки и геометрию, создавали новые идентификаторы точек и теряли сведения для фото. Account Trip сохранял пустые `photoRefs`, а PDF выводил список мест. Снимок печатной публикации уже поддерживал фото и атрибуцию.

## Решение

- Journey владеет областью поиска, каталогом, отбором и порядком точек. CoDoc владеет включением прогулки в выбранный день или остановку и печатью. Точки основного маршрута и транспорт сохраняются.
- Остаются `version: 1` и `type: private-walk:complete`. Хост проверяет origin, окно текущего iframe, channel, тип, последовательность рёбер, диапазоны и размеры известных полей. Лимиты составляют 200 точек, 199 рёбер, 30 000 координат, 7 кандидатов фото и 2,5 млн символов base64url для входящей ссылки. Неизвестные поля игнорируются.
- Необязательные поля сохраняют существующий ID прогулки и информацию о POI. Снимок содержит заметку отдельно от описания. Точка может указывать часы работы, источник, тему и кандидата фото. Снимок применяется при подтверждении. Старый payload без дополнительных полей применим.
- Один визит хранит одну присоединённую прогулку. Повторная передача обновляет присоединение. При повторе с тем же ID заметки CoDoc сопоставляются по ID POI. Удаление присоединения сохраняет основной маршрут. Старые открытые черновики используют записанные ранее точки и рёбра.
- Journey сохраняет свои заметки в черновике. CoDoc хранит свои заметки отдельно от описания и источника, обратной синхронизации нет. Routing сохраняет JSON Account Trip с `photoRefs` и `photoCredits` на точке. Document хранит изображение и использует существующий снимок для печатной публикации. Повторная генерация PDF учитывает актуальный снимок сохранённой поездки.

## Права и лимиты

Фото, видимое в карточке POI, остаётся материалом источника. Для печати принимаются явные Commons File и Wikidata P18. CoDoc требует автора, страницу файла и лицензию CC BY, CC BY-SA, CC0 или Public Domain Mark. Прямой URL Citywalls или другой внешний URL сам по себе не является разрешением на сохранение. Пользователь может отключить вложение фотографий.

Браузер CoDoc запрашивает метаданные и изображения только у заданных HTTPS-хостов Wikimedia, без учётных данных, нестандартных портов и редиректов. Общий дедлайн 20 секунд. Поток метаданных ограничен 1 МБ, изображение 900 КБ. Проверяются MIME, декодирование и размеры, затем формируется JPEG до 480×320. Существующий API медиахранилища принимает только байты. PDF читает активы по внутреннему ID и не разрешает внешние URL. Полный PDF поездки вмещает до 24 фотографий. При недоступном фото сохраняются нумерация, текст и карта.

Публичный API загрузки медиа не выдаёт юридическое подтверждение лицензии или связи байтов с оригиналом. Штатный клиент проверяет метаданные до загрузки, PDF дополнительно проверяет допустимость переданной атрибуции. Для независимого подтверждения каждой записи через произвольный API-клиент нужен серверный учёт происхождения активов и стратегия обработки исторических медиа.

## Откат

HTTP-пути, версии payload и схема БД сохраняются. Откат клиента не меняет сохранённый JSON Routing. Старый клиент продолжит читать обычные точки и геометрию. Изменения клиента, рендеринга PDF и fixtures выделяются в независимые commits.
