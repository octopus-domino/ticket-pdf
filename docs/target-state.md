# Целевая архитектура Journey

Существующие API публикаций, прогулок и PDF сохраняют свои пути и форматы. Новые сценарии планирования доступны при включённом `ENABLE_TRIP_PLANNER`. Черновик путешествия хранится локально до явного действия пользователя.

## Бэкенд

| Слой | Ответственность |
|---|---|
| `domain` | Модель поездки v2, календарные ограничения, координаты, геометрия, порты репозиториев и внешних источников |
| `application` | Создание поездки, миграция v1, импорт прогулки, выбор мест, расчёт маршрута, экспорт и публикация событий |
| `infrastructure` | JPA, существующая цепочка роутеров, подключение источников POI, расписания, отели и генерация PDF |
| `web` | HTTP-контракты, валидация запросов и преобразование ошибок |

Домен зависит от стандартной библиотеки и собственных типов. Прикладной код использует порты домена. Адаптеры реализуют порты. Контроллеры вызывают прикладные сценарии.

Для старого снимка модель v2 вычисляется при чтении. До проверки миграции на репрезентативных данных исходный снимок остаётся доступным в прежнем формате. Дата окончания поездки должна быть позже даты начала. Длительность переезда считается по двум моментам времени, отображение привязано к поясам отправления и прибытия.

Владелец может скачать JSON по `/api/trips/{id}/json`. Параметр `format=v1-compat` выдаёт сохранённый исходный снимок маршрута исторической публикации. Оба ответа используют `Cache-Control: no-store`.

## Фронтенд

Планировщик подключается к конструктору поездок CoDoc. Карта MapLibre, список дней, форма точных правок и сводка проживания читают один черновик. Изменения маршрута проходят через команды с отменой и повтором. Локальное состояние карты хранит камеру и незавершённый жест выделения.

Для импорта используется существующий контракт `SharedWalk`. При импорте создаётся копия точек и геометрии. Ссылки для чтения формируются отдельно от сохранённого черновика и исключают контакты попутчиков.

## Контракты поставщиков

Планировщик предлагает города и станции из справочника Яндекс Расписаний. При выборе станции используется её код в `from` или `to`. Адаптер держит справочник в ограниченном кэше и учитывает загрузку справочника в суточной квоте запросов. Просроченные результаты расписания помечаются в интерфейсе. [Справочник станций](https://yandex.ru/dev/rasp/doc/ru/reference/stations-list) [Расписание между станциями](https://yandex.ru/dev/rasp/doc/ru/reference/schedule-point-point)

Для загрузки отелей нужен бесплатный MCP с URL, инструментом поиска, схемой результата и условиями использования. Найденный WorldOTA MCP требует KEY ID и API KEY. Этот вариант не соответствует указанному в ТЗ поиску без ключа. [Описание WorldOTA MCP](https://mcpgate.ru/servers/ostrovok)

Поисковый интерфейс использует настраиваемый адаптер. `TRIP_HOTEL_MCP_URL` задаёт URL Streamable HTTP, `TRIP_HOTEL_MCP_TOOL` задаёт имя инструмента, `TRIP_HOTEL_CONNECT_TIMEOUT` и `TRIP_HOTEL_REQUEST_TIMEOUT` задают таймауты в формате Spring Duration. Контракт CoDoc передаёт `city`, `checkIn`, `checkOut` и `guests` и ожидает `structuredContent.hotels`. Это контракт адаптера CoDoc. Совместимость с конкретным MCP требует сверки с его схемой.

Резервная загрузка читает нормализованный JSON из `TRIP_HOTEL_REGISTRY_FILE`, например из примонтированного каталога `/app/data`. Каждая запись содержит `id`, `city`, `name` и при наличии `address`, `latitude`, `longitude`, `stars`, `rating`, `photoUrl`. Нужна реальная выгрузка реестра, преобразованная к этому формату. Статические карточки показываются без сведений о цене и наличии на выбранные даты.

Поиск городов использует настроенный экземпляр Nominatim с URL поиска в `TRIP_NOMINATIM_SEARCH_URL`. Запрос запускается кнопкой, принимает название города и возвращает населённые пункты с координатами. Публичный экземпляр OSMF имеет отдельные ограничения, включая запрет автодополнения. [Контракт поиска](https://nominatim.org/release-docs/latest/api/Search/) [Правила публичного API](https://operations.osmfoundation.org/policies/nominatim/)

Для расчёта бюджета используется датированный XML Банка России. Планировщик запрашивает таблицу курсов без данных поездки и пересчитывает введённые суммы локально. [Документация Банка России](https://cbr.ru/development/sxml/)
