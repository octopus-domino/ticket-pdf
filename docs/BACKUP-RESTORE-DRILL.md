# ARC-016. Backup and restore

`ticket-infra/deploy.sh` архивирует остановленный каталог Document `DATA_DIR`. Routing H2 хранится в отдельном именованном `routing-data` по `compose.routing.yml`, этот volume в архив не входит. `ticket-infra/scripts/deploy-postgres.sh` сохраняет логический dump обеих схем и конфигурацию выпуска. Файлы рядом с PostgreSQL, в том числе выдача генерации в `/app/data`, требуют согласованного файлового снимка. Drill останавливает оба синтетических писателя для снимка БД и файлов Document, записывает SHA-256 dump, архива и двух JAR и восстанавливает в новый именованный volume PostgreSQL/PostGIS.

| Состав | Политика восстановления |
| --- | --- |
| PostgreSQL public | Пользователи, рабочие пространства, документы, шаблоны, схемы, наборы, ревизии, публикации и media BLOB, настройки собственных операций. |
| PostgreSQL routing | Поездки, геометрия прогулок, атрибуция и ссылки на media ID. Исторические планы не заменяются пересборкой каталога. |
| H2 | Полный снимок должен включать обе остановленные БД и связанные файлы из `DATA_DIR` и `routing-data`. Деплой архивирует только `DATA_DIR`. |
| Файловое хранилище | Сохранять экспортируемые активы и выдачу, которая относится к бизнес-контракту. Временные OCR-файлы и кеши пересоздаются по правилам своего сервиса. |
| Конфигурация и ключи | Отдельный защищённый контур. Для восстановления нужны подходящая версия приложения, параметры схем, ключ шифрования интеграций и настройки JWT. |
| Gateway Redis | Хранение клиентских ключей и квот. При обязательном восстановлении client API нужен отдельный согласованный снимок. Тест остановки Redis проверяет fail closed. |

Перед восстановлением проверяются принадлежность каталога и Docker-ресурсов тестовому проекту, имя целевой БД, пустая схема, SHA-256 и читаемость каталога dump. `pg_restore` использует `--exit-on-error --single-transaction --no-owner`. Совместимость схемы при повторном запуске приложения подтверждается Hibernate validate. База создаётся через `TEMPLATE template0`. База, предварительно заполненная образом PostGIS, вызвала конфликт на схеме Tiger в первой попытке.

| Испытание на codoc.site | Результат |
| --- | --- |
| Артефакты и согласованный снимок | Dump обеих схем 65 038 Б, файловый архив 242 Б. Оба писателя остановлены перед копированием. Создание снимка и контрольных сумм заняло 2,436 с. |
| Восстановление базы | PostgreSQL 17/PostGIS 3.5, 29,063 с до завершения restore и SQL-проверок. Обе схемы и расширение PostGIS доступны. |
| Бизнес-проверка | Документ, история, публикация, бинарное фото и сохранённая поездка с атрибуцией совпали побайтно с результатами до снимка. При повторном запросе сгенерирован PDF прогулки. Приложения с исходными JAR стартовали с Hibernate validate. |
| Доступ | Некорректный bearer вернул 401. Посторонний тестовый аккаунт получил 404 для документа и поездки. |
| Отрицательные сценарии | Повреждённый dump отклонён при чтении каталога. Повторное восстановление в заполненную базу остановлено до записи. Отдельные unit-тесты проверили отсутствующий файловый архив, несовпадающий JAR и отказ при удалённом Docker endpoint. |
| Синтетический RTO | 138,806 с от запуска восстановления до чтения сущностей и повторного получения PDF. |

Серверный лог `server-restore-template0.log`. Проверка отсутствующего отдельного медиа в восстановленной базе, неверного ключа шифрования интеграций и искусственного несовпадения DDL при попытке восстановления остаётся открытой. `ClientApiSecurityTest` отдельным JVM-тестом подтверждает, что неверный ключ не расшифровывает запись. В запуске readiness отдельно доказан отказ при удалении доступа к обязательной таблице.

Среди проверенных синтетических записей потерь нет. Временной интервал между последней подтверждённой записью и остановкой писателей отдельно не измерялся. Для периодических снимков без PITR расчётный RPO при исправных заданиях определяется максимальным интервалом между подтверждёнными согласованными снимками. При наличии PITR расчёт также зависит от отставания и полноты архива WAL. Для диска требуется запас на исходный снимок, распакованную БД, архив файлов и временные операции восстановления. Замеры относятся к синтетическому сценарию.

Запуск воспроизводится командой PostgreSQL-профиля из [Production Safety](PRODUCTION-SAFETY.md). Для отката испытания достаточно удалить его временный Compose project после проверки владельца ресурсов.
