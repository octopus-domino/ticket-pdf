# Владение данными CoDoc

[JPA-реестр](architecture-evidence/data-tables.csv) содержит 29 явных отображений таблиц. [SQL-реестр](architecture-evidence/sql-objects.csv) отражает DDL и переносы. Схема production ниже следует из Compose и настроек, без чтения базы. Упоминание таблицы в скрипте переноса не делает её активной таблицей текущего приложения.

| Владелец | Схема | Таблицы и хранилища |
| --- | --- | --- |
| Document Auth, профиль и клиентский API | `public` | `users`, `client_profiles`, `api_client_keys`. Redis управляет состоянием отдельного шлюза Tyk. |
| Document Workspace | `public` | `folders`, `documents`. JSON структуры документа. Права владельца. |
| Document Schema, Model и Template | `public` | `schemas`, `data_schemas`, `data_models`, `templates`. Два отображения схем присутствуют в исходниках. Их консолидация потребует проверки сохранённых данных и ссылок. Связи входят в модель шаблона. |
| Document История и библиотека | `public` | `resource_revisions`, `asset_libraries`. Снимок ревизии и пользовательские библиотеки. |
| Document Integrations | `public` | `source_connections`, `email_deliveries`. SMTP-вызов и состояние доставки имеют разные жизненные циклы. |
| Document Journey | `public` | `public_journeys`, `journey_routes`, `journey_sites`, `journey_batches`, `journey_responses`, `journey_reviews`, `journey_albums`, `journey_media`, `journey_print_sources`, `poetry_sets`. `journey_routes` хранит совместимые публикационные снимки. Расчёт геометрии принадлежит Routing. |
| Document Workflow | `public` | `workflows`, `workflow_visits`, `site_addresses`. Адресное пространство используется и сайтами. Публикация маршрутизируется по владельцу адреса. |
| Routing Trip | `routing` | `journey_trip_drafts`. Черновики аккаунта. SQL переноса копирует данные из прежней таблицы. Старый источник сохраняется для совместимости и отката. |
| Routing Walks | `routing` | `building_history`, `mystic_places`. Индексация и импорт улиц/домов/POI не принадлежат конструктору. |

| Journey Web и Android | Browser storage, IndexedDB, приватное файловое хранилище Android | Черновики прогулок, индексы и кэши внешних карточек, запись GPS и её восстановление. Передача в поездку создаёт копию данных, а не перенос владения исходным треком. |
| Generation runtime | Память JVM и файловый каталог | Очередь `generationExecutor` принадлежит процессу. `DiskJobStore` хранит снимки статусов и задачи на диске. Готовые артефакты и TTL относятся к файловому хранилищу. Проверки восстановления различают документы, файлы задания и незавершённые работы. |

PostgreSQL настраивает Document с `currentSchema=public`, Routing с `currentSchema=routing,public` (`ticket-infra/compose.postgres.yml:53–76`). Это разделение моделей и схем. Общие credentials и fallback поиска схемы не дают доказательства строгой DB-изоляции. H2 использует отдельные пути и собственную схему Routing (`compose.routing.yml:17–20`).

## Транзакционные границы

| Сценарий | Граница по источнику |
| --- | --- |
| Публикация, пакет, получение владельца | `JourneyService` и `PublicationsService`. Чтение помечается `readOnly`. `PublicationsService.java:102–142` выполняет claim в транзакции Data Store с блокировкой публикации. HTTP-ключ нужно доказать перед присвоением владельца. |
| Конструктор и печатный снимок | `JourneyConstructorService` использует `TransactionTemplate`; `JourneyPrintSourceService` сохраняет печатный источник отдельно от обычного редактирования шаблона. Генерация сама по себе не создаёт транзакцию между JVM. |
| Аккаунтная поездка | `routing-service/src/main/java/ru/ticket/routing/trip/TripDrafts.java:32–70` ограничивает чтение владельцем и оборачивает запись в транзакцию. `TripDraft.java` хранит ссылку на владельца и содержимое. Авторизация Document идёт по HTTP. |
| Версии | `history/ResourceHistory.java` предоставляет операции чтения и записи ревизий. Оптимистическую версию JPA и историю пользовательских снимков нужно учитывать как разные примитивы при восстановлении. |
| Переезд БД | `psql --single-transaction` выполняет отдельный скрипт. Транзакция одного SQL-файла не охватывает последовательность shell-этапов. Этапы до и после DDL имеют разные сценарии отката. |

[Реестр 104 аннотаций](architecture-evidence/transactions.csv) включает класс и метод, атрибуты и строки. `TransactionTemplate`, авто-транзакции Spring Data, HTTP-зависимости и порядок вызовов следует сверять по исходнику. Аннотация в статическом графе не доказывает прохождение прокси Spring при self-invocation.

## Хранилища, кэши, очереди и жизненный цикл

- Документы, снимки и права хранятся транзакционно в JPA. Изменяемую рабочую копию, выпущенную публичную ссылку и печатный снимок нельзя считать одним объектом жизненного цикла.
- Файловые артефакты генерации обслуживает отдельная уборка. Адаптер `generation/infrastructure/DiskJobStore.java:14–63` относится к persistence, даже когда работа выполняется в локальном executor. При рестарте гарантии очереди и сохранность выбранного результата проверяются отдельно.
- Провайдерные кэши адресов, POI, дорог, погоды, стихов, отелей и расписаний находятся у соответствующих адаптеров. Размеры, TTL и условия резервных источников различаются. Например, общий адресный кэш Photon ограничен 512 записями и регулирует частоту новых запросов.
- `Redis` участвует в эксплуатации Tyk. Исходники поколения документов не используют его как распределённую очередь.
- В `private_jorney` браузерный и нативный recorder используют разные адаптеры. Восстановление трека после закрытия вкладки или остановки процесса зависит от соответствующего адаптера и проверяется отдельно от серверного восстановления.
